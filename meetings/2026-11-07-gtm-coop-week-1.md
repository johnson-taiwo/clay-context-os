# GTM Co-op - week 1 class (7 Nov 2026)

**Facilitator:** Bolaji Anifowose. **Format:** live class, about 5 hours. **Topic:** GTM systems thinking, ICP and
signals, Claude Code, building a Context OS, GitHub.

## Key points

- **Design the system before picking tools.** Tools change every quarter; systems compound.
- **Four pillars of a GTM system:** clean data, signals, small reusable parts ("like a car: swap the tyre, it still
  runs"), feedback loops.
- **ICP** = the companies that get the most value, buy fastest and stay longest. It moves over time. Build it from CRM
  data when you have it, from research and beta customers when you don't.
- **Personas change with company size:** the founder at 20 staff; HR + finance at 200.
- **Signals:** pick one mother intent (e.g. hired 5+ people in 30 days), filter to the ICP, stack one secondary signal
  (e.g. 30% growth, new funding) and change the copy line per stack. Check each signal's **volume** and **refresh rate**
  (hiring = weekly, leadership change = monthly).
- **Data types:** first party (your site, CRM), second party (shared with partners), third party (public web, vendors).
- **Context OS:** one folder Claude Code reads every session: CLAUDE.md, context (ICP, personas, messaging, brand
  kit), knowledge base, learnings, meetings, outputs, tools, weekly priorities, worklog. Agencies: one subfolder per
  client with shared skills.
- **Worklog:** log every action as it happens, so a new chat can pick up where the last one stopped.
- **Keys:** in `.env`, git-ignored, never pasted into chat. 1Password CLI for teams.
- **GitHub:** version history (roll back an ICP), sharing by clone, branches + pull requests for review.
- **Skills:** turn any repeated task into a slash command.
